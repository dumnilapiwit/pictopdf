# PictoPDF — developer handoff

## เป้าหมาย
เว็บภาษาไทยสำหรับเลือกรูปสไลด์ที่ถ่ายจากจอหรือโปรเจคเตอร์ แก้มุม ตัดขอบ ปรับแสง จัดลำดับ แล้วรวมเป็น PDF หนึ่งไฟล์เพื่ออ่านทบทวน ใช้ได้บนโทรศัพท์และคอมพิวเตอร์

## เริ่มพัฒนา
แตก PictoPDF-source.zip แล้วเปิดโฟลเดอร์นั้นด้วยเครื่องมือพัฒนา เช่น Claude Code หากใช้ Claude แบบแชต ให้แนบไฟล์ทั้งสี่ใน dist/ และเอกสารนี้ หรือแนบ ZIP หากระบบรองรับ

เป็นเว็บ HTML/CSS/JavaScript แบบ static ไม่ต้องติดตั้งแพ็กเกจหรือมี API key ใช้ Python เปิดทดสอบได้:

    python -m http.server 8000 --directory dist

เปิด http://localhost:8000 ในเบราว์เซอร์ บนระบบที่ใช้ python3 ให้เปลี่ยนชื่อคำสั่งตามนั้น

## โครงสร้าง
- dist/index.html: หน้าภาษาไทย ตัวเลือกรูป ตัวแก้มุม และแผงบันทึก PDF
- dist/style.css: หน้าตาและ responsive layout ใช้ Google Fonts จึงมีคำขอภายนอกสำหรับฟอนต์
- dist/detector.js: findScreen(data, width, height) ตรวจแนวขอบสว่าง-มืดที่ต่อเนื่องและยาว คืน points, confidence, found
- dist/app.js: โหลดรูป จัดลำดับ ลากมุม แปลง perspective ด้วย homography และ bilinear interpolation ปรับแสง เขียน PDF ฝัง JPEG และสร้างลิงก์ Blob สำหรับดาวน์โหลด/เปิด/แชร์

## พฤติกรรมที่มีแล้ว
- รองรับ JPEG, PNG, WebP สูงสุด 60 รูป ย่อด้านยาวเหลือไม่เกิน 1800 px
- ทำงานในเบราว์เซอร์ ไม่มี backend หรือการส่งรูปไปประมวลผลบนเซิร์ฟเวอร์
- ไม่ได้ใช้ AI/LLM/OCR และไม่ได้สร้างข้อความหรือส่วนของภาพที่ขาดหาย
- ตัวหาขอบทำงานบนภาพย่อด้านยาว 480 px ค้นขอบรอบนอกด้วย slope/offset search และใช้คะแนนความต่อเนื่อง/ความต่างแสง
- ถ้าพบขอบน้อยกว่า 2 ด้านหรือพื้นที่เล็กเกินไป จะใช้ภาพเต็ม หากพบเพียงบางด้านจะคงด้านที่ไม่แน่ใจไว้ที่ขอบภาพ พร้อมให้ผู้ใช้ตรวจ
- PDF ปัจจุบันเป็น A4 แนวนอนหนึ่งรูปต่อหน้า ใช้ภาพ JPEG ไม่มีข้อความ searchable
- ขั้นตอนบันทึก: สร้าง PDF ให้เสร็จก่อน แล้วแสดงปุ่มบันทึก PDF / เปิด PDF / แชร์ไฟล์บนเบราว์เซอร์ที่รองรับ ไม่พึ่งการดาวน์โหลดอัตโนมัติหลังงาน async
- Blob URL ไม่หมดอายุระหว่างรอผู้ใช้บันทึก และเปลี่ยนชื่อไฟล์ตามจำนวนหน้า/เวลา เพื่อลดสับสนกับไฟล์เก่า
- ระหว่างสร้าง PDF ล็อกการแก้รูปและการเพิ่มรูป พร้อม snapshot รายการหน้า
- รูปและไฟล์ชั่วคราวหายเมื่อรีเฟรช/ปิดหน้า ยังไม่มีระบบบันทึกงานค้าง

## สิ่งที่ต้องพัฒนาต่อ
1. เพิ่มความแม่นยำของกรอบ: ภาพจอมืด จอขาว ผนังสว่าง แสงสะท้อน มุมแรง ขอบหลุดนอกภาพ และวัตถุบัง ตัวตรวจปัจจุบันเป็น heuristic และยังไม่ครอบคลุมกรณีเหล่านี้ หลีกเลี่ยงเลือกกรอบภาพประกอบภายในสไลด์แทนกรอบจอ
2. ทดสอบ Safari บน iPhone/iPad และ Chrome Android จริง โดยเฉพาะ download/share Blob, การลากมุม และภาพจำนวนมาก ยังไม่ได้ยืนยันบนเครื่องผู้ใช้จริง
3. ลดหน่วยความจำ: ตอนนี้เก็บ canvas ทุกภาพไว้ อาจหนักบนมือถือเมื่อเลือกรูปหลายสิบรูป ควรเก็บรูปบีบอัดและ decode ทีละหน้า พิจารณา worker สำหรับงานแปลงภาพ
4. รองรับ HEIC/HEIF หากจำเป็น ปัจจุบันไม่รองรับและต้องแจ้งไฟล์ที่เปิดไม่ได้อย่างชัดเจน
5. เพิ่ม resume/save draft ใน IndexedDB และเตือนเรื่องงานค้างก่อนออกจากหน้า
6. เพิ่มการทดสอบ PDF ทั้งจำนวนหน้า การเรียงหน้า ความถูกต้องของภาพ และการเปิดในตัวอ่านหลายชนิด รวมกรณี crop ผิดหรือรูปเสีย

## การตรวจที่ทำแล้วและขอบเขต
- รูปจริง 3 รูปที่ถ่ายจอจากด้านข้าง: ตัวตรวจใหม่พบกรอบบางด้าน ไม่ใช่ครบทุกมุม
- ทดสอบ synthetic: กรอบสว่างบนพื้นมืด และภาพที่ไม่มีขอบชัดต้องเก็บภาพเต็ม
- ทดสอบ PDF writer 1, 3, 60 หน้า และอ่านด้วย pypdf แบบ strict ตรวจจำนวนหน้าและหนึ่งภาพต่อหน้า
- ทดสอบผ่านเบราว์เซอร์ desktop: เลือกรูปจริงสามรูป ดูผลลัพธ์ สร้างไฟล์ กดบันทึกจริง และตรวจ PDF ที่ดาวน์โหลดได้ครบสามหน้า
- การทดสอบ PDF writer 60 หน้าไม่ได้แปลว่าทดสอบโหลด/ประมวลผลภาพ 60 รูปบนมือถือแล้ว

## การเปลี่ยนแปลง v3 (Claude, 2026-11-06)
- เขียน dist/detector.js ใหม่: หา "บริเวณสว่างที่ใหญ่และใกล้กลางภาพ" (Otsu threshold + connected component) แล้วขยายเข้าส่วนที่มืดกว่าแบบ hysteresis เพื่อรับแสงไม่สม่ำเสมอบนจอ ใช้ convex hull ปิดรูภาพประกอบ/ตัวอักษรมืดในสไลด์และวัตถุที่บัง เลือกสี่เหลี่ยมพื้นที่มากสุดจาก hull แล้ว fit เส้นขอบแต่ละด้านซ้ำ 3 รอบ
- ขอบจอที่หลุดนอกภาพจะชิดขอบรูป และไม่นับเป็นด้านที่พบ (confidence = partial)
- API เดิม findScreen(data,w,h) → {points, confidence, found} ไม่เปลี่ยน app.js ไม่ต้องแก้
- ทดสอบแล้ว: รูปจริง 3 รูป กรอบตรงขอบจอทั้ง 3 รูป (รวมจอที่แสงซีกซ้ายมืดกว่า) / synthetic: ภาพเรียบ → ภาพเต็ม, กล่องสว่าง และกล่องที่มีภาพมืดข้างใน → ได้มุมตรง / desktop browser: โหลด 3 รูป ดูผลลัพธ์ สร้าง PDF 3 หน้า
- ยังไม่ได้ทดสอบ: มือถือจริง (Safari/Chrome Android), จอมืด/โปรเจคเตอร์ในห้องมืด, ผนังขาวติดกับจอโดยไม่มีกรอบดำ

## การเปลี่ยนแปลง v4 — ปรับภาพอัตโนมัติ
- เพิ่ม autoClean() ใน dist/app.js (เปิดเป็นค่าเริ่มต้น ปิดได้ทีละรูปด้วยช่อง "ปรับภาพอัตโนมัติ")
- ประเมินแสงพื้นหลังเฉพาะจุดแยกตามช่องสี แล้วหารออก ทำให้แสงไม่สม่ำเสมอและสีฟ้าของจอหายไป พื้นจึงขาว จากนั้นตั้งจุดดำให้ตัวหนังสือเข้ม และล้างสีอ่อนๆ ที่ค้างอยู่บนพื้นขาว
- จำกัดการเร่งความสว่างไว้ไม่เกินประมาณ 1.7 เท่า เพื่อไม่ให้ภาพเอกซเรย์หรือภาพมืดขนาดใหญ่ซีด
- ค่าเริ่มต้นของความต่างแสงเปลี่ยนจาก 105 เป็น 100 (ไม่ปรับเพิ่ม) เพราะ autoClean ทำหน้าที่นี้แล้ว
- ทดสอบบน desktop browser: รูปจริง 3 รูป พื้นขาวและข้อความชัดขึ้น ภาพเอกซเรย์ยังคงอยู่ สร้าง PDF 3 หน้าใช้เวลาประมาณ 0.7 วินาที ยังไม่ได้ทดสอบความเร็วบนมือถือ

## การเปลี่ยนแปลง v5 — พร้อมใช้บนมือถือ
- หน่วยความจำ: เก็บรูปเป็น JPEG บีบอัด และ decode เฉพาะรูปที่กำลังแก้ ผลทดสอบ 30 รูปใช้ heap ประมาณ 54 MB
- ความเร็ว: ใช้ toDataURL แทน toBlob (toBlob ถูกหน่วงประมาณ 1 วินาทีต่อหน้า) ผลบน desktop: เปิด 30 รูปใช้ 1.7 วินาที สร้าง PDF 30 หน้าใช้ 8 วินาที
- แถบปรับค่าคำนวณผลแบบหน่วงเวลาและเก็บ cache ไว้
- ลากมุมด้วยนิ้วง่ายขึ้น: พื้นที่แตะ 48px จุดมุมใหญ่ขึ้น
- รับไฟล์รูปทุกชนิด (image/*) และแจ้งชื่อไฟล์ที่เปิดไม่ได้ เช่น HEIC
- เตือนก่อนออกจากหน้าเมื่อยังมีรูปอยู่ · ชื่อ PDF เป็นรูปแบบ PictoPDF-YYYYMMDD-HHMM-Np.pdf
- PWA: manifest, ไอคอน, service worker (sw.js) เพิ่มลงหน้าจอโฮมและเปิดออฟไลน์ได้ (เฉพาะบน https)
- ทดสอบแล้ว (Chrome จำลองจอ 375×812): โหลด 12/30 รูปรวมไฟล์เสีย 1 ไฟล์, ลากมุมด้วย touch, ดูผลลัพธ์, แถบปรับค่า, หมุน, ลบ, สร้าง PDF 11/30 หน้า
- ยังไม่ได้ทดสอบ: iPhone/Android จริง, service worker บน https, เพิ่มลงหน้าจอโฮม

## นำขึ้น GitHub Pages
1. สร้าง repo บน GitHub แล้ว push โฟลเดอร์ PictoPDF-source เข้า branch main
2. Settings → Pages → Source เลือก "GitHub Actions" (.github/workflows/pages.yml จะนำ dist/ ขึ้นเว็บ)
3. เว็บจะอยู่ที่ https://<username>.github.io/<repo>/
4. ทุกครั้งที่แก้ไฟล์ ให้เปลี่ยน VERSION ใน dist/sw.js และเลข ?v= ใน index.html

## การเปลี่ยนแปลง v6: หาขอบสไลด์โปรเจคเตอร์ได้ดีขึ้น
- detector.js สร้างกรอบผู้สมัครหลายแบบ ได้แก่ convex hull และการ fit เส้นตรงแต่ละด้านด้วย RANSAC บน threshold หลายระดับ แล้วเลือกกรอบที่ขอบทั้ง 4 ด้านสว่างด้านใน มืดด้านนอกชัดเจนที่สุด ถ้ามีด้านไหนอ่อน จะลดคะแนนกรอบนั้น
- แก้กรณีโต๊ะสีขาวหรือผ้าจอติดกับสไลด์จนกรอบลากลงไปถึงขอบรูป
- ทดสอบกับรูปจริง 10 รูป (จอ TV 3 รูป, โปรเจคเตอร์ 5 รูป, จอ LED 2 รูป): ถูกต้อง 7 รูป, รูปหนึ่งตัดคอลัมน์ขวาที่มืดของสไลด์ออก, จอ LED ในงานประชุมทั้ง 2 รูปยังรวมผู้ชมด้านล่างเข้ามา (ต้องลากมุมเอง)
- ทดสอบภาพจำลอง: ภาพเรียบ, กล่องสว่าง, กล่องที่มีภาพมืดข้างใน, กล่องที่มีโต๊ะขาวอยู่ด้านล่าง ผ่านทั้งหมด
